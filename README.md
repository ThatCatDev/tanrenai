# Tanrenai (鍛錬AI)

A three-tier LLM system written in Go: a GPU inference server, an orchestration backend, and clients with agentic tool use, context windowing, and memory/RAG.

## Architecture

```
Clients (clients/)  →  Backend (server/)  →  GPU Server (gpu/)
CLI, Desktop           memory/RAG, proxy,    llama-server,
agent loop             vast.ai mgmt          models, fine-tuning
```

### GPU Server (`gpu/`)

Pure inference and training tier. Manages llama-server subprocesses and exposes an OpenAI-compatible API:

- `POST /v1/chat/completions` — streaming and non-streaming inference
- `POST /v1/embeddings` — embedding generation
- `POST /tokenize` — token counting
- `POST /api/load` — model loading (auto-detects context length from GGUF metadata)
- `GET /v1/models`, `POST /api/pull` — model listing and download
- `POST /v1/finetune/*` — fine-tuning

### Backend (`server/`)

Orchestration layer. Owns memory/RAG, manages vast.ai GPU instances, and proxies inference requests to the GPU server:

- Proxies completions, tokenize, and model endpoints to GPU
- Memory/RAG: store, search, list, and delete memories (backed by chromem-go vector store)
- Instance management: start, stop, and monitor vast.ai instances

### Clients (`clients/`)

- **CLI** (`clients/cli/`) — Interactive REPL with agent mode, tool calling, context windowing, and memory
- **Desktop** (`clients/desktop/`) — Desktop application (in development)
- **Shared** (`clients/shared/`) — Shared packages extracted for multi-client reuse

## Quick Start

### CLI (three-tier setup)

Run the GPU server, backend, and CLI as separate processes:

```bash
# 1. Build
cd gpu/    && go build -o tanrenai-gpu .
cd server/ && go build -o tanrenai-server .
cd clients/cli/ && go build -o tanrenai .

# 2. Start GPU server
./gpu/tanrenai-gpu serve --port 11435

# 3. Start backend
./server/tanrenai-server serve --gpu-url http://localhost:11435 --memory --port 8080

# 4. Run the CLI
./clients/cli/tanrenai run <model-name> --agent --memory --server-url http://localhost:8080
```

### Desktop GUI

The desktop app is a GTK4/Adwaita application that embeds both the GPU server and backend in-process — no separate server setup needed.

**Prerequisites:** GTK 4 and libadwaita development libraries.

```bash
# Ubuntu/Debian
sudo apt install libgtk-4-dev libadwaita-1-dev

# Fedora
sudo dnf install gtk4-devel libadwaita-devel

# Arch
sudo pacman -S gtk4 libadwaita
```

```bash
# Build and run
cd clients/desktop/
go build -o tanrenai-desktop .
./tanrenai-desktop
```

## Context Size

The context window size is automatically detected from GGUF model metadata. When you load a model, the GPU server reads the model's native context length and returns it through the backend to the CLI, which uses it for context windowing.

- **Auto-detect (default):** `--ctx-size 0` — uses the model's native context length (e.g., 32768 for Qwen3)
- **Manual override:** `--ctx-size 8192` — explicitly set a context size, overriding the GGUF value

```bash
# Auto-detect: uses model's native context length
tanrenai run qwen3-8b --agent

# Override: force 8192 tokens
tanrenai run qwen3-8b --agent --ctx-size 8192
```

Use `/tokens` in the REPL to see the active context budget.

## Agent Mode

The CLI supports an agentic tool-calling loop with these built-in tools:

`file_read`, `file_write`, `patch_file`, `list_dir`, `find_files`, `grep_search`, `git_info`, `shell_exec`, `web_search`

```bash
tanrenai run <model-name> --agent
```

## Memory / RAG

Enable persistent memory across conversations with hybrid vector search:

```bash
tanrenai run <model-name> --agent --memory
```

Memories are stored in a chromem-go vector database with embeddings generated by the GPU server.

## Project Structure

```
gpu/                  # Tier 1: GPU inference server (Go module)
  internal/runner/    #   llama-server subprocess management
  internal/models/    #   model store, download, manifest
  internal/training/  #   fine-tuning pipeline

server/               # Tier 2: Orchestration backend (Go module)
  internal/gpuclient/ #   HTTP client to GPU server
  internal/memory/    #   chromem-go vector store, hybrid search
  internal/vastai/    #   vast.ai instance management

clients/cli/          # Tier 3: CLI client (Go module)
  internal/agent/     #   agent loop with stuck detection
  internal/chatctx/   #   token-budgeted context windowing
  internal/tools/     #   tool registry and implementations

clients/desktop/      # Desktop client (Go module, in development)
clients/shared/       # Shared packages for clients
```

Three independent Go modules communicating via JSON over HTTP.
